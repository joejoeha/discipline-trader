# 架构说明

## 分层

1. React 页面仅依赖 `TradingGateway`，不直接接触 Tauri IPC。
2. `TauriGateway` 将统一类型映射为桌面命令；`DemoGateway` 提供不保存密钥的浏览器预览。
3. Rust `ExchangeAdapter` 为 MEXC 与 Ourbit 分别实现签名、字段映射和能力矩阵。
4. 风控层在交易所适配器之前执行，生成一次性订单复核令牌。
5. SQLite 保存计划、模拟交易、订单映射、复盘、风险事件与审计；Windows Credential Manager 保存密钥。

## 行情数据路径

- MEXC：REST 加载历史 K线与盘口快照；WebSocket 推送 ticker、最新K线、逐笔成交和增量盘口。深度版本不连续时立即丢弃本地盘口并重新抓取快照。
- Ourbit：独立使用其合约 REST 地址刷新 K线与盘口。由于当前公开合约文档未给出期货 WebSocket 频道，首版不复用现货频道、不伪造实时来源；适配器边界保留后续接入位置。
- 任一行情源断开时 `connected=false`，实盘风控可据此锁定新风险；已有仓位的减仓、平仓和撤单仍保持可用。
- Ourbit 实盘账户在进入实盘前强制同步，进入后每 5 秒轮询余额、持仓和挂单。同步失败会锁定新增风险并保留最后一次账户视图，方便用户继续执行减仓、平仓或撤单。

## 资产路由与成本

- `AssetClass` 将合约分为加密货币、股票、原油和贵金属。默认路由为：加密货币 → Ourbit；股票、原油、贵金属 → MEXC。
- 路由是账户级可编辑设置。行情列表按类别筛选并显示推荐交易所；选择合约时自动切换，手动覆盖会在最终复核中警告。
- 每个交易所维护独立的 Maker/Taker API 费率档案与核对时间。网页/App 活动费率不被当成 API 费率。
- 下单复核使用十进制定点数计算 Maker/Taker 费用，并按当前资金费率绝对值估算一个资金结算周期的成本。

## 开仓门槛

交易计划已创建 → 计划已启用 → 触发条件命中 → 冷静期结束 → 清单满足所选模式 → 全局风险通过 → 最终确认 → 模拟撮合或交易所适配器。订单不能替换计划的交易所、合约、方向和止损；止盈若填写，必须来自计划目标位。

`warn` 只允许用户确认纪律问题，不能绕过杠杆、名义价值、止损风险、日亏、行情状态、账户同步与时间偏差。`off` 只关闭问题清单。

## 行情

历史 K 线通过 REST 加载。`DepthSynchronizer` 要求增量版本连续；发生断档后丢弃本地盘口并重新取快照。重连使用指数退避，尊重 `Retry-After`，连接在 24 小时之前主动轮换。

## 订单幂等

每单携带不超过 32 字符的唯一客户端订单 ID。复核令牌只能消费一次。超时、408 或 5xx 先按客户端 ID 查询交易所状态，状态仍不确定时返回 `unknown` 并禁止自动重发。
